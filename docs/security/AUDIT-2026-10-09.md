## 1. CSP allowed inline scripts: Medium
- **Location:** `next.config.ts` (static CSP header): `script-src 'self' 'unsafe-inline' …`
- **Type:** XSS defense-in-depth gap.
- **Description:**
  - The app renders user HTML in four places: writeup bodies, comments, war-room notes and the editor preview.
  - With `'unsafe-inline'`, the sanitizers are the only barrier. A single bypass (a future allow-list change or a parser differential) would run script as the viewer, and that script could call Server Actions with the viewer's session.
- **Remediation:** a per-request nonce with `'strict-dynamic'`, set in the proxy. Next.js stamps the nonce on its own scripts; the root layout passes it to the one inline script.

```ts
// src/proxy.ts
function newNonce(): string {
  const bytes = crypto.getRandomValues(new Uint8Array(16));
  return btoa(String.fromCharCode(...bytes));
}

export default clerkMiddleware(
  async (auth, req) => {
    if (isMemberRoute(req)) await auth.protect();
    const nonce = newNonce();
    const csp = contentSecurityPolicy(nonce); // script-src 'self' 'nonce-…' 'strict-dynamic' …
    const requestHeaders = new Headers(req.headers);
    requestHeaders.set("x-nonce", nonce);
    requestHeaders.set("Content-Security-Policy", csp); // Next reads the nonce from here
    const res = NextResponse.next({ request: { headers: requestHeaders } });
    res.headers.set("Content-Security-Policy", csp);
    return res;
  },
  (req) => ({ authorizedParties: [req.nextUrl.origin] }),
);
```
```tsx
// src/app/layout.tsx
const nonce = (await headers()).get("x-nonce") ?? undefined;
<script nonce={nonce} dangerouslySetInnerHTML={{ __html: fxInitScript }} />
<ClerkProvider nonce={nonce} …>
```
- **Notes:**
  - `style-src` keeps `'unsafe-inline'` because React `style` props and Framer Motion need it. It deliberately has no nonce, since a nonce would make browsers ignore `'unsafe-inline'`.
  - Every HTML page is now rendered per request, which is required for nonces. Most pages already were (`connection()`).
  - Clerk's built-in `contentSecurityPolicy` option was not used: its defaults always add Stripe, Google Maps and telemetry origins and `script-src https:`.

## 2. Rate limiter not atomic: Medium
- **Location:** `src/lib/security/rate-limit.ts` `hit()`: `const count = Number(await kv.get(k) ?? 0) + 1; await kv.put(k, …)`.
- **Type:** rate-limit bypass (check-then-act race).
- **Description:**
  - N parallel requests all read the same KV count and all pass. This affects every limit, e.g. comments, publish (5/day), team and event creation, and Markdown preview (CPU-heavy, up to 100 KB per call).
  - The upload quota and invite `max_uses` were already enforced atomically in D1, and invite codes (40-bit entropy, HMAC-stored) stay impractical to brute-force.
- **Remediation:** an atomic burst guard from Cloudflare's Workers Rate Limiting binding in front of the KV window.

```jsonc
// wrangler.jsonc
"ratelimits": [
  { "name": "RL_STRICT", "namespace_id": "1001", "simple": { "limit": 3, "period": 10 } },
  { "name": "RL_BURST", "namespace_id": "1002", "simple": { "limit": 10, "period": 10 } }
]
```
```ts
// src/lib/security/rate-limit.ts
export async function hit(store: RateStore, key: string, limit: Limit, now = Date.now()): Promise<RateResult> {
  const burst = limit.strict ? store.RL_STRICT : store.RL_BURST;
  if (burst && !(await burst.limit({ key })).success) return { ok: false, remaining: 0, retryAfter: BURST_PERIOD_SEC };
  // …existing KV fixed window for the long (minutes–day) limits…
}
```
`strict: true` is set on invite redeem, team/event creation, join requests and publishing.

## 3. `decideRequest` didn't validate `decision`: Low
- **Location:** `src/app/teams/actions.ts` `decideRequest`.
- **Type:** missing input validation.
- **Description:**
  - Server Action arguments come from the client. Any value other than `"reject"` fell through to the approve path, adding the member while recording the request as `rejected` with a `request.approve` audit row. Only team leads can call the action.
  - Two concurrent approvals both passed the "pending" check. The loser was then reported as "joined another team".
- **Remediation:**
```ts
if (decision !== "approve" && decision !== "reject") return { error: "Invalid decision." };
// …
const claimed = await db.update(joinRequests).set(decided)
  .where(and(eq(joinRequests.id, req.id), eq(joinRequests.status, "pending")))
  .returning({ id: joinRequests.id });
if (claimed.length === 0) return { error: "That request is no longer pending." };
```

## 4. Captaincy race could leave a team without a captain: Low
- **Location:** `teams/actions.ts` `transferCaptaincy` and `leaveTeam`.
- **Type:** race condition / integrity.
- **Description:**
  - If the transfer target left between the check and the write, the batch demoted the captain and promoted nobody. The team then had no captain, and the captain-only actions (rename, roles, transfer) became permanently unavailable.
  - `leaveTeam` used a role read earlier in the request, so a member promoted to captain mid-request could still leave.
- **Remediation:** the demote only runs while the target is still on the team, all inside one transaction (D1 batch). `leaveTeam` re-checks the role in its delete.
```ts
const targetStillHere = sql`exists (select 1 from ${teamMembers} where ${teamMembers.teamId} = ${team.id} and ${teamMembers.userId} = ${userId})`;
const [demoted] = await db.batch([
  db.update(teamMembers).set({ role: "co_captain" })
    .where(and(eq(teamMembers.teamId, team.id), eq(teamMembers.userId, member.id), eq(teamMembers.role, "captain"), targetStillHere))
    .returning({ userId: teamMembers.userId }),
  db.update(teamMembers).set({ role: "captain" }).where(and(eq(teamMembers.teamId, team.id), eq(teamMembers.userId, userId),
    sql`not exists (select 1 from ${teamMembers} where ${teamMembers.teamId} = ${team.id} and ${teamMembers.role} = 'captain')`)),
]);
if (demoted.length === 0) return { error: "That person isn't on the team any more." };
```
```ts
// leaveTeam
db.delete(teamMembers).where(and(eq(teamMembers.teamId, team.id), eq(teamMembers.userId, member.id), ne(teamMembers.role, "captain")))
```

## 5. `kickMember` acted on a stale role: Low
- **Location:** `teams/actions.ts` `kickMember`.
- **Type:** race condition / privilege.
- **Description:** the delete only excluded `captain`. A co-captain could remove a member who had just been promoted to co-captain, which `can()` normally forbids.
- **Remediation:**
```ts
const kickable = TEAM_ROLES.filter((r) => can(base.role, "member.kick", r));
db.delete(teamMembers).where(and(eq(teamMembers.teamId, team.id), eq(teamMembers.userId, userId), inArray(teamMembers.role, kickable)))
```

## 6. Event owners could re-lock other authors' writeups: Low
- **Location:** `src/app/events/actions.ts` `updateEvent`.
- **Type:** authorization (cross-author griefing).
- **Description:**
  - Any writeup can link to any visible event, and editing the event rewrote `spoilerUntil` on every linked writeup.
  - An event owner could move an upcoming event far into the future, or extend a running one, and hide other authors' writeups, including ones that were already readable.
- **Remediation:** only writeups that are still locked follow the event's new end.
```ts
const stillLocked = (eventId: string, now: number) => and(eq(writeups.eventId, eventId), gt(writeups.spoilerUntil, new Date(now)));
db.update(writeups).set({ spoilerUntil: v.endsAt }).where(stillLocked(event.id, now))
```

## 7. `deleteEvent` could wipe a newly registered team: Low
- **Location:** `events/actions.ts` `deleteEvent`.
- **Type:** race condition / data loss.
- **Description:** the "no other teams registered" count and the delete weren't atomic. A team registering in between lost its registration and war-room data through `ON DELETE CASCADE`.
- **Remediation:** every write re-checks the condition in the same transaction.
```ts
const noOthers = sql`not exists (select 1 from ${eventRegistrations} where ${eventRegistrations.eventId} = ${event.id} and ${eventRegistrations.teamId} <> ${viewer.team!.id})`;
const [, deleted] = await db.batch([
  db.update(writeups).set({ spoilerUntil: null }).where(and(eq(writeups.eventId, event.id), noOthers)),
  db.delete(events).where(and(eq(events.id, event.id), noOthers)).returning({ id: events.id }),
]);
if (deleted.length === 0) return { error: "Events can only be deleted before they start and before other teams register." };
```

## 8. Hidden event's title shown on writeup pages: Low
- **Location:** `src/app/w/[handle]/[slug]/page.tsx` (linked-event lookup).
- **Type:** data leakage.
- **Description:** hiding an event doesn't unlink writeups. The writeup page showed the hidden event's title and slug to every reader, but elsewhere hidden events are visible only to staff and the owning team.
- **Remediation:**
```ts
const event = linkedEvent && (!linkedEvent.hiddenAt || staff || linkedEvent.ownerTeamId === viewer.teamId) ? linkedEvent : null;
```

## 9. Draft titles written to the team audit log: Low
- **Location:** `src/app/writeups/actions.ts` `deleteWriteup`.
- **Type:** data leakage.
- **Description:** deleting a draft tagged with a team wrote its title to that team's audit log. Team leads can read the log, but only the author could ever see the draft. If the author had left the team, the title went to their old team.
- **Remediation:**
```ts
w.publishedAt
  ? auditEntry({ teamId: w.teamId, actorId: member.id, action: "writeup.delete", targetId: w.id, meta: { title: w.title } })
  : auditEntry({ teamId: null, actorId: member.id, action: "writeup.delete", targetId: w.id })
```

## 10. Comments accepted on moderator-hidden writeups: Low
- **Location:** `src/app/w/[handle]/[slug]/actions.ts` `addComment`.
- **Type:** authorization (moderation bypass).
- **Description:** the page hid the comment box on hidden writeups, but the action didn't check `hiddenAt`. The author (the only non-staff reader) could keep a moderated thread going by calling the action directly.
- **Remediation:** `if (w.hiddenAt) return { error: "Comments are closed on this writeup." };`

## 11. Authors could lose the ability to delete their comments: Low
- **Location:** `w/[handle]/[slug]/actions.ts` `deleteComment`.
- **Type:** user control over their own data.
- **Description:** deleting went through the writeup read check. After the writeup was unpublished, hidden or spoiler-locked, the author couldn't remove their own comment.
- **Remediation:** authorship alone authorizes the soft delete.
```ts
const deleted = await db.update(comments)
  .set({ deletedAt: new Date(), bodyMd: "", bodyHtml: "" })
  .where(and(eq(comments.id, commentId), eq(comments.authorId, member.id), isNull(comments.deletedAt)))
  .returning({ writeupId: comments.writeupId });
```

## 12. `editComment` had no rate limit: Low
- **Location:** `w/[handle]/[slug]/actions.ts` `editComment`.
- **Type:** missing rate limit (CPU cost).
- **Description:** each edit re-renders Markdown and can be repeated without limit inside the 15-minute edit window.
- **Remediation:** `const rl = await hit(getEnv(), \`comment:${member.id}\`, LIMITS.comment);`, sharing the comment budget.

## 13. Client IP fell back to `X-Forwarded-For`: Low
- **Location:** `teams/actions.ts` `clientIp`.
- **Type:** spoofable input used for a security control.
- **Description:** the invite-redeem IP limit fell back to the client-controlled `X-Forwarded-For` header. That only matters if the Worker is ever reached without Cloudflare's edge, but there's no reason to trust it.
- **Remediation:** `return h.get("cf-connecting-ip");`

## 14. Image metadata stripped from JPEG only: Low
- **Location:** `src/app/api/uploads/route.ts`, `src/lib/uploads/sniff.ts`.
- **Type:** privacy / data leakage.
- **Description:** PNG `eXIf`/`tEXt`/`iTXt`/`zTXt`/`tIME` chunks and WebP `EXIF`/`XMP` chunks (GPS, device, author) were stored and served publicly as uploaded.
- **Remediation:** `stripPngMetadata` and `stripWebpMetadata` (the latter also clears the VP8X flags and rewrites the RIFF size), called through `stripMetadata(buf, type)`. Bytes after the PNG `IEND` chunk are dropped too. Tests are in `sniff.test.ts`.

## 15. Images stayed public after a writeup was deleted: Low
- **Location:** `writeups/actions.ts` `deleteWriteup`.
- **Type:** privacy (data retention).
- **Description:** images were only removed by a manual sweep at least 7 days later, and still counted against the 100 MB quota until then.
- **Remediation:** delete the writeup's upload rows in the same batch, then the R2 objects. Images that another of the author's writeups still embeds are kept.
```ts
const images = await db.select({ id: uploads.id, r2Key: uploads.r2Key }).from(uploads).where(and(
  eq(uploads.writeupId, w.id), eq(uploads.ownerId, member.id),
  sql`not exists (select 1 from ${writeups} where ${writeups.authorId} = ${member.id} and ${writeups.id} <> ${w.id} and instr(${writeups.bodyMd}, ${uploads.id}) > 0)`,
));
// …batch deletes rows…
await getEnv().UPLOADS.delete(images.map((i) => i.r2Key));
```
**Residual:** objects are served with `Cache-Control: public, max-age=31536000, immutable`, so Cloudflare's edge can keep serving a deleted image until it is evicted or purged. If takedowns must be immediate, purge the URL by API on delete or shorten the TTL.

## 16. Clerk `authorizedParties` not set: Low
- **Location:** `src/proxy.ts`.
- **Type:** session hardening (CSRF / token-origin binding).
- **Description:** Clerk recommends limiting which origins' session tokens the middleware accepts.
- **Remediation:** `(req) => ({ authorizedParties: [req.nextUrl.origin] })`. A token is accepted only when it was minted for the origin serving the request: `app.securityexile.com` in production, and localhost for `next dev` / `npm run preview`.

## 17. CI token had default permissions: Low

- **Optional:** pin `actions/checkout` and `actions/setup-node` to commit SHAs.

## 20. Upload origin response headers: Low, ops action
- **Location:** Cloudflare dashboard → `files.securityexile.com`.
- **Type:** defense in depth for user content.
- **Description:**
  - Uploads are checked by magic bytes, so a valid image header followed by HTML is stored as `image/*`. Browsers don't sniff `image/*` into HTML, and the separate origin keeps any script away from the app's cookies.
  - R2 custom domains add no `nosniff` or CSP by default.
- **Remediation (not in code):** add a Response Header Transform Rule for host `files.securityexile.com`:
  - `X-Content-Type-Options: nosniff`
  - `Content-Security-Policy: default-src 'none'; sandbox`
  - `Cross-Origin-Resource-Policy: cross-origin`
